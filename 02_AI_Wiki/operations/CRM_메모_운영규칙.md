# CRM 메모 운영 규칙 — 스마트CRM 기준

> CX 교육자료 부록 "차트 메모란 3칸 운영안"을 **스마트CRM 기준으로 다시 정리**한 것.
> 원 강의 자료는 베가스(차트 메모란이 여러 칸으로 고정된 구조)를 전제로 "메모 3칸"이라 했다. 우리는 베가스에 저장하지 않고 **스마트CRM**을 쓰며, 메모 구조가 다르다. 그래서 이 문서는 **칸 번호가 아니라 메모의 역할 3가지**를 기준으로 쓴다. 어떤 기능에 붙일지는 §3 매핑표에서 정한다.
> 🔧 §3 매핑표는 **총괄실장이 스마트CRM 화면을 보고 채운다**(2026-09-07 1:1 과제). 채워지기 전까지 `status: draft`.

## 1. 원칙 — 칸이 아니라 역할

교육자료 PART 1의 "고객이 느껴야 할 3문장"은 각각 **다른 종류의 기록**에서 나온다. 기록의 종류가 다르면 쓰는 시점·읽는 시점·수명이 다르다. 그래서 세 역할을 **한 곳에 섞어 쓰지 않는다.**

| 역할 | 담는 것 | 수명 | 쓰는 시점 | 읽는 시점 | 만들어내는 문장 |
|---|---|---|---|---|---|
| **A · PROFILE** (사람) | 호칭 선호 · 담요/온도 · 음료 · 통증 민감도 · 대기 선호 · 주차 · 알러지/금기 | 거의 안 변함. 바뀔 때만 수정 | 최초 내원 | 도착 · 대기 · 시술 준비 | "오늘 내가 원하는 걸 이미 알고 있네" |
| **B · LAST VISIT** (직전 방문) | 방문일 + 시술명 + **고객이 말한 아쉬운 점(원문)** + 특이 반응 | 매 방문 덮어씀 | 귀가 시 **당일 마감** | 재예약 통화 · 내원 · 시술 전 | "지난번 불편하다고 했던 걸 기억하고 있네" |
| **C · NEXT** (다음 행동) | 다음 예약일 · 진행 중 플랜 단계 · **팔로업 때 물어볼 질문 한 문장** | 실행하면 지움 | 상담 · 귀가 시 | 팔로업 · 상담 시작 | "지난번 시술 결과를 먼저 물어봐 주네" |

## 2. 스마트CRM에 붙일 때의 기준 — "읽는 순간에 보이는가"

메모는 **읽는 순간에 화면에 떠야** 의미가 있다. 어느 기능에 어느 역할을 붙일지는 이 기준 하나로 정한다.

| 역할 | 반드시 보여야 하는 순간 | 그래서 필요한 것 |
|---|---|---|
| A · PROFILE | 고객이 **도착**했을 때, 시술 **준비**할 때 | 예약판·접수 화면에서 **클릭 없이** 보이거나, 접수 시 팝업 |
| B · LAST VISIT | **재예약 통화** 중, 내원 시 | 예약 잡는 화면(전화 받으며 보는 화면)에서 바로 보임 |
| C · NEXT | **팔로업 연락** 할 때, 상담 시작할 때 | 팔로업 대상 조회 시 보임. 상담 화면에서 보임 |

**이 기준으로 보면 스마트CRM의 메모 기능은 대개 아래 셋 중 하나에 속한다.** (기능 이름은 원내 화면 기준으로 §3에서 확정)

- **고객 단위 메모** — 고객 정보에 붙어 계속 남는 것 → A · PROFILE 후보
- **예약 단위 메모** — 그 예약(방문)에만 붙는 것. 예약판에서 보임 → B · LAST VISIT 후보 (단, 다음 예약을 잡을 때 직전 예약 메모가 보이는지 확인 필요)
- **상담·시술 기록** — 회차별 기록 → C · NEXT의 "플랜 단계" 후보. "팔로업 질문 한 문장"은 팔로업 화면에서 보이는 곳에

스마트CRM에 **태그·고객 분류·알림 메모(팝업)** 기능이 있으면 A · PROFILE 중 "반드시 놓치면 안 되는 것"(알러지·금기·통증 민감)만 거기에 옮긴다. 나머지는 일반 메모에.

## 3. 매핑표 — 총괄실장 확인 후 확정

| 역할 | 스마트CRM 기능명 (화면 표기 그대로) | 위치 (어느 화면 · 어느 탭) | 접수·예약판에서 클릭 없이 보이나 | 글자수 제한 | 작성자 표시 · 수정 이력 | 확정 |
|---|---|---|---|---|---|---|
| A · PROFILE | | | | | | ☐ |
| A 중 금기·알러지 | | | | | | ☐ |
| B · LAST VISIT | | | | | | ☐ |
| C · NEXT | | | | | | ☐ |
| C 중 팔로업 질문 | | | | | | ☐ |

**확인 절차** — ① 스마트CRM 고객 상세 화면, 예약판 팝업, 상담 기록 화면 **스크린샷 3장** 확보 → ② 위 표 채움 → ③ 원장 확인 → ④ 이 문서 `verified`, 교육자료 부록 갱신

**매핑이 어려울 때의 차선책** — 스마트CRM 메모 칸이 하나뿐이면, **한 칸 안에서 접두어로 구분**한다.
```
[P] 담요 항상 / 아메리카노 아이스 / 통증 민감·마취 20분↑
[L] 0715 울쎄라 300샷 "라인 정리가 조금 아쉬워요" 통증 호소 3회→출력↓
[N] 0910 14:00 / 플랜 1st / Q: "지난번 신경 쓰인다던 턱선은 어떠세요?"
```
[L]과 [N]은 갱신 시 이전 줄을 지운다. [P]는 남긴다. 접두어가 있어야 다른 직원이 "무엇을 지워도 되는지" 안다.

## 4. 작성 규칙 5 — 시스템과 무관하게 동일

| # | 규칙 | 이유 |
|---|---|---|
| 1 | **고객의 말은 원문 그대로, 따옴표로** — `"라인 정리가 좀 아쉬워요"` | 요약하면 재예약 때 쓸 문장이 안 나온다 |
| 2 | **주관적 평가·감정 표현 금지** — 관찰된 사실과 요청만 | 메모는 **고객이 볼 수도 있다는 전제**. ❌ "까다로움" → ⭕ `"상담 30분 이상 선호"` · ❌ "예민함" → ⭕ `"통증 민감 · 마취크림 추가 요청"` |
| 3 | **B · LAST VISIT는 귀가 시 당일 마감** | 다음날로 넘기면 문장이 소실된다 |
| 4 | **C · NEXT는 실행하면 지운다** | 남아 있으면 다음 사람이 이미 한 말을 또 한다 |
| 5 | **날짜를 앞에 붙인다** — `0826` | 최신순 판별. 스마트CRM이 작성일을 자동 표시하면 생략 가능 (§3에서 확인) |

**규칙 2는 교육 사항이 아니라 규정이다.** CRM 메모는 진료기록의 일부로 취급될 수 있다(의료법 §21 기록 열람·사본 발급 대상 가능성). 전 직원 준수.
