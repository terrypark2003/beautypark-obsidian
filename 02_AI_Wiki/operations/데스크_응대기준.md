# 데스크 응대 기준 — 6장면

> 전화 예약부터 대기까지, 데스크에서 가장 자주 나오는 6개 장면의 **기준 멘트**. 총괄실장 CX 세션에서 정리된 결과다.
> 원칙은 하나다. **닫는 말 대신 여는 말을 쓴다.**

## 다섯 원칙

1. **닫지 말고 묻는다** — 예약 확인으로 시작하지 않고 고민을 먼저 듣는다
2. **기억 말고 메모를 본다** — 히스토리는 외우는 게 아니라 [[CRM_메모_운영규칙]]·차트에서 읽는다 (통증 민감·추가 고민·담요 요청)
3. **거절 대신 대안을 준다** — 안 되는 시간만 말하고 끝내지 않는다
4. **"잠시" 대신 숫자로 말한다** — 대기는 분 단위로 안내한다
5. **요청 전에 먼저 챙긴다** — 담요·물은 요청을 기다리지 않는다

## 1. 예약 목적 파악

| | |
|---|---|
| ✕ | "울쎄라 보고 연락주셨는데 예약 도와드릴까요?" |
| ✓ | "어떤 부분이 고민이실까요?" |
| ✓ | "해당 시술 받아보신 적 있으실까요?" |
| ✓ | (시술 이력 있을 경우) "효과는 어떠셨을까요?" |

닫는 말: 우선 울쎄라로 **예약 메모**해 두고 "정확한 시술 방향은 내원하셔서 상담 후 안내 도와드리겠습니다."

**전화로 시술을 확정하지 않는다.** 시술 결정은 의사 진료 영역이고, 데스크가 전화로 효과를 단정하면 내원 후 상담 결과와 어긋나 분쟁 소지가 된다. 문의 시술은 **예약 메모로만** 남긴다.

## 2. 재예약 — 히스토리 반영

| | |
|---|---|
| ✕ | "울쎄라 이번에도 예약 도와드릴까요?" |
| ✓ | (통증 민감 고객) "이전에 울쎄라 시술 받으시고 통증은 어떠셨을까요?" |
| ✓ | "이전에 울쎄라 받으실 때 추가 고민이 있다고 하셨는데, 이번에 같이 상담 도와드릴까요?" |

**이 멘트는 메모가 있어야 나온다.** 전화를 받기 전 스마트CRM 메모를 먼저 본다. 통증 민감·추가 고민 같은 정보는 [[CRM_메모_운영규칙]]의 **A PROFILE**(지속 특성)과 **B LAST VISIT**(지난 방문)에 기록되어 있어야 한다. 메모가 비어 있으면 이 장면은 실행 불가다.

## 3. 마감된 시간대 응대

| | |
|---|---|
| ✕ | "그 시간은 예약이 어렵습니다" |
| ✓ | "말씀주신 시간대는 먼저 예약주신 분들이 많으셔서 예약이 어려운 상태라, 가장 가까운 시간대가 4시와 5시인데 편하신 시간대가 있으실까요? 아니시면 다른 시간대 말씀주시면 스케줄 확인 도와드리겠습니다." |

거절로 끝내지 않는다. **대안 시간 2개를 먼저 제시**하고, 그래도 맞지 않으면 고객이 말한 시간을 확인해 드린다. 위 시간(4시·5시)은 예시이며 실제 스케줄에 맞춰 말한다.

## 4. 도착 응대

| | |
|---|---|
| ✕ | "예약 확인해드릴게요. 성함이 어떻게 되세요?" |
| ✓ **성함을 아는 단골** | "OOO님, 안녕하세요." — 이름을 먼저 불러 드린다 |
| ✓ **성함을 모를 때** | 성함을 먼저 여쭙고, 그다음 "OOO님 예약 확인되셨고, 접수 바로 도와드리겠습니다. 이전 시술 후 불편하셨던 점은 없으실까요?" |

**아는 분께 성함을 되묻지 않는다.** 자주 오시는 분에게 매번 이름을 확인하면 "나를 모르는구나"가 된다. 예약자 명단으로 미리 확인해 둔다.

**모르는 분께는 여쭙는 것이 맞다.** 다만 이름을 확인한 뒤에는 반드시 이름으로 부른다. 확인만 하고 계속 "고객님"으로 부르지 않는다.

## 5. 대기가 발생했을 때

| | |
|---|---|
| ✕ | "잠시만 기다려주세요" |
| ✓ 1차 | 대략적이라도 **분 단위로 대기시간을 먼저 안내**한다. "대기가 있을 수 있다"로 두지 않는다. |
| ✓ 2차 | (그 이후로도 지연되면) "대기시간으로 불편을 드려 죄송합니다. 앞 시술이 예상보다 길어지고 있는데, 제가 안쪽에 최대한 빠르게 준비해 달라고 한 번 더 말씀드렸고, 대기하실 동안 **차나 커피 준비 도와드리도록 하겠습니다.**" |
| ✓ 동행 분 | 동행하신 분이 대기실에 계속 계시면 **음료대 옆 한적한 자리**로 안내해 드리고, 드실 수 있는 음료도 함께 안내한다 |

2차 멘트의 핵심은 **사과 → 이유 → 내가 한 조치 → 대접** 순서다. 이유만 말하고 조치를 말하지 않으면 변명이 된다.

동행 분은 시술을 받지 않으시므로 안내에서 빠지기 쉽다. **대기가 길어질수록 동행 분의 체감이 고객의 체감이 된다.**

## 6. 대기 중

| | |
|---|---|
| ✕ | 고객이 요청하면 물이나 담요를 제공한다 |
| ✓ | 체감 온도는 고객마다 다르므로 **간호팀·피부팀이 사전에 체크해서 미리 준비**해 드린다 |
| ✓ | **담요 요청 이력은 차트에 남긴다.** 다음 방문 때 차트를 먼저 보고 미리 챙겨 드린다 |

요청을 기다리지 않는다. 먼저 여쭤보고 먼저 가져다 드린다. 데스크 단독이 아니라 **간호팀·피부팀과 함께 움직이는 항목**이다.

**두 번째부터는 여쭙기 전에 준비되어 있어야 한다.** 담요는 성격상 [[CRM_메모_운영규칙]]의 **A PROFILE**(방문마다 유지되는 특성)에 해당한다. 기록 위치를 차트로 할지 CRM 메모로 할지 정해야 데스크·간호팀·피부팀이 같은 곳을 본다.

## 인쇄물

**데스크 응대 기준 6장면** (A4 1장, 코팅) — 2026-09-10 제작, 데스크 비치. 위 6장면의 ✕/✓ 멘트와 다섯 원칙을 한 장에 담았다. 원내 배포이며 저장소에 포함하지 않는다. **이 노트가 바뀌면 인쇄물을 다시 뽑는다.**

## 후속

- [ ] 대기시간 안내 기준 — 몇 분 단위로, 어느 시점에 2차 멘트로 넘어가는지 확정
- [ ] 차·커피 준비 절차 — 누가, 무엇을, 어디서. 제공 가능한 음료 목록 확정
- [ ] **동행 분 안내 공간** — 음료대 옆 한적한 자리가 어디인지 지정, 좌석 확보 여부
- [ ] **담요 요청 이력 기록 위치 확정** — 차트인지 스마트CRM 메모 A PROFILE인지. 두 곳에 흩어지면 아무도 안 본다
- [ ] 사전 온도 체크 시점 — 간호팀·피부팀 중 누가 언제 확인하는지 [[운영_SOP]]에 반영
- [ ] 3번 대안 시간 제시가 가능하려면 데스크가 실시간 스케줄을 볼 수 있어야 함 — 현행 확인
- [ ] 총괄실장·원장 검토 후 `verified` 상신
